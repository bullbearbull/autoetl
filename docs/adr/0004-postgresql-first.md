# ADR-0004: PostgreSQL 우선 — 다른 DB는 sqlglot 방언 변환으로 확장

- 상태: 수락됨 (2026-11-04, 계획 확정 사항 기반)
- 결정 주체: 소유자

## 맥락

대상 DB를 여러 개 동시에 지원하면 DDL 생성, 타입 매핑, 적재(COPY)의 품질이 전부 얕아진다.
하나의 DB에 집중해야 타입 매핑 정밀도, 제약 검증, 시험 적재·적재 실행 품질을 벤치로 증명할
수 있다. 데이터 웨어하우스·분석 용도에서 PostgreSQL은 로컬 설치·운영 비용 대비 기능이
좋은 편이다.

## 결정

DDL, 타입 매핑, 적재(COPY)를 PostgreSQL 기준으로 먼저 만든다.

- 타입 매핑: 통계 기반 decimal 정밀도, varchar 길이, timestamptz 등 PostgreSQL 타입 체계를
  기준으로 한다.
- 적재: 임시 스키마 시험 적재 → 위반 리포트 → COPY 적재, 실패 행 격리.
- 다른 DB가 필요해지면 sqlglot 방언 변환으로 넓힌다(변환 결과는 시험 적재로 재검증).

## 대안

- **처음부터 멀티 DB(SQLite·MySQL·Oracle 동시)**: 표면적 호환성은 넓어지지만 DB별 특성
  (JSONB, 파티셔닝, BRIN, COPY)을 살리는 설계가 불가능하고 벤치 기준도 흐려진다.
- **SQLite 우선**: 설치는 가장 쉬우나 COPY 대량 적재·동시성·타입 체계가 분석 적재 용도에
  부족하다.

## 결과

- 긍정: 한 DB의 깊은 기능(JSONB, 파티셔닝·BRIN, COPY, 임시 스키마 시험 적재)을 온전히
  활용하는 품질을 먼저 증명할 수 있다.
- 부정: PostgreSQL이 아닌 DB를 쓰는 사용자의 초기 요청은 방언 변환 레이어가 나올 때까지
  받을 수 없다. 변환 레이어의 검증 비용이 나중에 든다.
