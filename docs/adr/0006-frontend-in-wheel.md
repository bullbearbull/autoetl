# ADR-0006: 프런트엔드 — Vite SPA 빌드 결과물을 휠에 포함

- 상태: 수락됨 (2026-11-04, 계획 확정 사항 기반)
- 결정 주체: 소유자

## 맥락

로컬 설치형 사용자에게 UI가 필요하다(화면 10개: 작업 목록, 데이터 입력, 분석 진행, 결과,
후보 비교, 적재 플랜, LLM 설정, 시스템·로컬 모델, 벤치마크, 감사). 사용자 PC에 Node.js를
요구하면 `autoetl ui` 한 줄 실행 목표가 깨진다. 반면 개발은 최신 프런트 도구 체계로 하고
싶다.

## 결정

React + TypeScript + Vite SPA로 개발하고, 빌드 결과물(정적 파일)을 Python 휠에 포함한다.

- 라이브러리: ECharts(차트), React Flow(ERD), Monaco(DDL 편집기).
- 로컬 서버(FastAPI)가 127.0.0.1에서 정적 파일을 서빙하고 REST/SSE로 통신한다.
- 사용자는 `autoetl ui` 한 줄로 UI를 연다. Node.js는 개발·빌드 때만 필요하다.
- 빌드 산출물은 릴리스 파이프라인에서 휠에 함께 패키징한다(소스 저장소에는 빌드 결과물을
  넣지 않는다).

## 대안

- **Electron·PyWebview 데스크톱 앱**: 배포·업데이트·플랫폼 빌드 관리 비용이 크고 웹
  기술의 서버형 재사용(확장 9)이 어려워진다.
- **Node.js를 사용자 PC에 요구(개발 서버 그대로 실행)**: 설치 장벽과 보안 노출이 커진다.
- **서버 원격 UI만 제공**: 1차 목표인 로컬 설치형 사용자 경험과 어긋난다.

## 결과

- 긍정: pip 설치만으로 UI가 함께 오고 `autoetl ui` 한 줄 실행이 가능하다. 로컬 서버가
  127.0.0.1 전용이므로 노출이 최소화된다. 서버형(확장 9)도 같은 정적 자산을 재사용한다.
- 부정: 휠 크기가 커진다. 프런트 빌드 파이프라인을 릴리스에 묶어야 하고, UI 변경은
  파이썬 릴리스 주기와 동반된다. 개발 중 핫 리로드를 쓰려면 로컬에서 Node 개발 환경이
  필요하다.
