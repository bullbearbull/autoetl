# 계약 버전 규칙

단계별 입출력 계약(S0~S14 산출물)은 `docs/PLAN.md`의 "계약 우선" 원칙에 따라
버전 관리 대상이다. 변경은 소유자 검토 관문(AGENTS.md 3절)을 밟는다.

## 버전 체계

- 전체 계약 묶음 버전: `CONTRACTS_VERSION`(common.py). 현재 0.x(v0 시리즈).
- 각 루트 산출물 모델은 `contract_version` 필드로 묶음 버전을 기록한다. 파이프라인
  산출물에는 계약 버전이 함께 남아 나중에 해석할 수 있다.
- **0.x 동안**: 필드 추가·설명 완화는 패치·마이너로 올릴 수 있다(기존 데이터는 여전히
  유효). 필드 제거·이름 변경·타입 강화는 호환 깨짐이므로 버전을 올리고 이전 산출물과의
  변환기를 둔다.
- **1.0부터**: 의미론적 버전을 엄격히 지킨다. additive는 minor, breaking은 major.

## JSON Schema

`tools/export_contracts.py`가 `ARTIFACTS` 레지스트리의 15개 루트 계약을
`schemas/<이름>.schema.json`으로 내보낸다. 파일은 저장소에 커밋하고, CI 테스트가
재생성 결과와 커밋된 파일이 같은지 확인해 schemas/가 뒤처지지 않게 한다.

스키마 파일 하나는 독립적으로 읽힌다(공통 타입이 각 파일의 `$defs`에 반복된다).

## 규칙

- 모든 계약 모델은 `ContractModel`을 상속한다(`extra="forbid"`). LLM 출력 강제와
  계약 검증이 같은 정의를 쓴다.
- LLM이 만드는 판단(S8 의미 해석, S11 권고, S3 임계치 미달 판정)은 `Evidence` 인용을
  필수로 둔다. 없는 ID나 통계와 모순된 주장은 검증기가 반려한다.
- 비율(rate, confidence)은 0~1, 점수는 0~100, 식별자 이름은 소문자 스네이크
  (`^[a-z][a-z0-9_]*$`)로 통일한다.
